# Ventic Pro V13C — Conversion Flow

## الهدف

تقليل أي احتكاك قبل الطلب وزيادة نسبة العملاء الذين يتركون بيانات تواصل قابلة للمتابعة.

## تجربة العميل الجديدة

عند فتح `/order` تظهر شاشة اختيار قبل الفورم:

### 1) طلب سريع
العميل يكتب فقط:
- الاسم
- رقم الموبايل

ثم يتم تسجيل Lead فورًا، ويظهر في:
`/admin/leads`

ويصل إشعار Admin بعنوان:
`طلب سريع جديد`

### 2) طلب بالتفاصيل
قبل دخول الفورم الكبير، يتم التقاط:
- الاسم
- رقم الموبايل

ثم يتم حفظ Lead فورًا، وبعدها يدخل العميل رحلة الطلب الحالية.

لو خرج العميل قبل إنهاء الطلب، بياناته الأساسية تكون محفوظة بالفعل للمتابعة.

## الحقول الإلزامية في الطلب الكامل

بيانات العميل الإلزامية:
- الاسم
- رقم الموبايل

الباقي اختياري:
- البريد الإلكتروني
- المحافظة
- المنطقة
- العنوان
- التاريخ
- الفترة
- مصدر المعرفة

تبقى الموافقة على الشروط مطلوبة عند إنشاء Order فعلي لأنها موافقة قانونية وليست حقل بيانات.

تم تحويل Checkbox "أفهم أن السعر تقديري" إلى ملاحظة واضحة بدل إجبار العميل على Checkbox إضافي.

## Quick Lead anti-duplicate

طلبات Gate بنفس رقم الهاتف خلال 24 ساعة يتم تحديث نفس Lead بدل إنشاء عدة Leads من الضغط المكرر أو Refresh.

## Attribution

UTM / attribution الحالي يظل كما هو. لذلك رابط TikTok مثل:
`/order?utm_source=TikTok&utm_medium=bio&utm_campaign=soft_launch`
يدخل على شاشة الاختيار الجديدة مع استمرار حفظ attribution.

## لا توجد Migration

V13C لا تغير Prisma schema ولا قاعدة البيانات.

## طريقة التطبيق

1. اعمل Pull لأحدث `main`.
2. فك ZIP.
3. انسخ محتويات مجلد:
   `Ventic-Pro-V13C-Conversion-Flow`
   إلى Root مشروع `ventic-pro`.
4. وافق على إضافة/استبدال الملفات.
5. شغل:
   `APPLY-V13C.cmd`
   Double click.
6. يجب أن تظهر رسالة:
   `V13C conversion patch applied successfully.`
7. افتح GitHub Desktop وراجع الملفات.
8. Commit:
   `V13C - quick request and low friction order conversion`
9. Push.

## لماذا يوجد APPLY-V13C.cmd؟

ملف `app/order/page.tsx` كبير وحساس وبه الصور والتسعير والكوبونات والـLead tracking.
بدل استبداله بنسخة كاملة، V13C تعمل Patch محدد على V13B الحالية:
- تجعل بيانات العميل الاختيارية اختيارية فعليًا؛
- تقرأ الاسم والموبايل المحفوظين من Gate؛
- تقلل Validation النهائي؛
- تحافظ على باقي منطق الطلب الحالي كما هو.

إذا لم يجد الـPatch النص المتوقع، يتوقف ولا يكمل بدل تعديل ملف غير مطابق بالخطأ.

## Smoke Test

### Quick Request
1. افتح `/order`.
2. اختر `طلب سريع`.
3. اكتب اسم + موبايل.
4. Submit.
5. تأكد أن Success screen ظهرت.
6. افتح `/admin/leads`.
7. تأكد أن Lead ظهر.
8. تأكد من Admin notification: `طلب سريع جديد`.

### Detailed Request abandonment
1. افتح `/order`.
2. اختر `طلب بالتفاصيل`.
3. اكتب الاسم والموبايل.
4. اضغط `ابدأ التفاصيل`.
5. اقفل الصفحة بدون إكمال.
6. تأكد أن Lead موجود في `/admin/leads`.

### Detailed Request completion
1. اختر طلب بالتفاصيل.
2. الاسم والموبايل فقط إلزامي.
3. اترك Email / Address / Date / Time فارغين.
4. أكمل الخدمة.
5. وافق على الشروط.
6. تأكد أن Order يتم إنشاؤه.
7. تأكد أن Admin order page تعمل طبيعيًا.

## ملاحظة تشغيلية

لو العميل لا يحدد عنوانًا في الطلب التفصيلي، يتم حفظ `غير محدد` داخليًا للعقار حتى يكتمل لاحقًا من خدمة العملاء.
ولو لا يحدد موعدًا، الرسالة تشير إلى أن الموعد سيتم تحديده بالتواصل.
